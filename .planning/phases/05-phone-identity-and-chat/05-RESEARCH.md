# Phase 05 client feasibility research

The D-056 physical gate uses a disposable `spikes/phone-feasibility` app. It is a measurement fixture, not the selected product client. Use the official Expo `blank-typescript` template, then record the generated SDK and exact lockfile versions before building. Do not copy a moving `latest` dependency into the product plan without the measured result.

## Package Legitimacy Audit

| Package | Status | Official source and reason |
|---|---|---|
| `create-expo-app` | VERIFIED | [Expo create-expo-app documentation](https://docs.expo.dev/more/create-expo/) documents the `blank-typescript` template and `--no-install`. |
| `expo`, `react`, `react-native`, `typescript` | VERIFIED | Generated by Expo's official `blank-typescript` template; preserve its exact lockfile and SDK compatibility. |
| `expo-secure-store` | VERIFIED | [Expo SecureStore documentation](https://docs.expo.dev/versions/latest/sdk/securestore/) documents `npx expo install expo-secure-store` and platform behavior. |
| `expo-audio` | VERIFIED | [Expo Audio documentation](https://docs.expo.dev/versions/latest/sdk/audio/) documents installation, recording permissions and platform behavior. |
| `expo-background-task`, `expo-task-manager` | VERIFIED | [Expo BackgroundTask documentation](https://docs.expo.dev/versions/latest/sdk/background-task/) documents installation and OS scheduling limits. |

Before `npm ci` or `expo install`, inspect the generated package names, registry metadata and exact lockfile against these official sources; if a package identity differs, stop and require independent review. The executor records exact package versions, checksums and native build IDs in `05-01-EVIDENCE.md`. Background task scheduling is opportunistic; a successful scheduled callback does not prove immediate reconnect. Measure actual suspend, reconnect and outbox recovery on each physical device. Expo Go alone cannot establish the native permission/background gates; use device-installed development builds.
