# Later-phase execution contracts

This file is binding context for Phase 11–17 plans. Each executor must resolve the named decision and write its evidence before dependent code. `PASS` requires the automated check **and** the live/manual gate for every advertised configuration. Missing provider access, hardware, owner decision, license proof or elapsed duration means `BLOCKED`; unsupported integration remains disabled. Evidence records revision, exact OS/arch/runtime/provider version, command, redacted IDs, negative case, receipt and reviewer. Never store credentials, prompts or customer content.

## 11 — messaging

`11-01` pins one provider API version and Hermes gateway version, proves authenticated sender identity, stable inbound event/thread IDs, outbound idempotency or receipt lookup, webhook retry order, edit/delete mapping, attachment limits, rate limits and credential custody on a disposable account. Save a redacted request/response fixture and official API references in `11-01-EVIDENCE.md`. Owner approves actual account link after this artifact. If Hermes lacks the typed seam, freeze a native bridge and mark the Hermes option unsupported. `11-02` may start only after that decision and owns canonical link, inbound dedupe and outbound intent state plus migration. `11-03` authenticates ingress before the one message/receipt transaction. `11-04` hooks the existing `ConversationSend` path so an explicitly selected owner-origin message commits one outbound attempt in the same State transaction; provider-origin ingress never echoes to its source link. `11-05` must run the real linked web/phone↔provider journey, reconnect, revoke and post-revoke denial; local Go tests cannot satisfy that gate.

## 12 — Apple and browser

Version `reminder.manage/create` as an action under the existing `reminder.manage` capability ID, with explicit account/list/target, local macOS consent, exact approval and external receipt. `12-01` freezes native EventKit versus Hermes skill; `12-02` must rewrite its file list and checks to that choice before code. Native route requires Swift tests plus Host broker/receipt test and live Mac permission/lost-ACK evidence; Hermes route requires its own pinned runtime profile and Host proof. First browser submit slice explicitly denies credentials, payments, uploads, downloads, 2FA, file URLs, internal network and unapproved account changes. `12-04` requires preview digest and fresh page/form/account recheck immediately before one external submit; absent post-submit receipt yields `uncertain`.

## 13 — coding and nodes

`coding.run` produces an artifact in a disposable workspace and never mutates the canonical checkout. `coding.apply` is a separate one-use approved effect targeted to the repository node. Stage patch in a temporary worktree from the approved base commit; verify patch digest, clean base and permissions; prepare all changes there; atomically publish only after all validations pass. If publication cannot be atomic on the selected filesystem/adapter, require manual apply or mark the adapter unsupported. Persist apply intent/receipt before acknowledgement; lost ACK queries receipt, never blindly reapplies. Test Swift node sandbox and apply code, Host authorization, web preview, process cancellation, path escape and partial publish. `13-04` must implement one actual Windows or Linux adapter per claimed platform with owned source, tests, secure key storage, local grants and crash recovery; until it does, mark that platform `UNSUPPORTED`. Generic fixture tests are only protocol evidence. `13-01/02` persist coding checkpoint sequence, workspace/Run identity and reattach cursor so disconnect/restart reconciles instead of redispatching. `13-05` qualifies selected Hermes skills and MCP through immutable Host-owned transitive capability/credential profiles. `13-06` completes the reachable owner review UI after the canonical apply routes. Phase 14-04 owns final FR-39 closure after bounded Hermes delegation and every earlier facet; absent safe seams stay `BLOCKED/UNSUPPORTED`.

## 14 — automation and delegation

Use canonical `internal/store` transaction and `internal/space` command path for schedule, occurrence, lease, parent and child records. Add versioned schema/migration and replay fixture before scheduler dispatch. The Host dispatch insertion point is `internal/host/execution.go`; a claimed occurrence creates one Host Run intent and one approval, then the existing exact-action broker owns effects. Commit occurrence key `(schedule_id, schedule_version, nominal_utc_time)` before claiming lease; persist epoch and compare it at every state transition and effect dispatch. On lease loss, query Run and target receipts; never blindly repeat unknown effects. States: `draft→active↔paused→revoked`; occurrence `scheduled→claimed→waiting_approval→running→succeeded|failed|uncertain|cancelled`. Pause prevents new occurrences and preserves current run state; resume requires current grant/policy/revision and does not replay missed runs except declared missed-run policy. Parent cancellation fences descendants; parent projection shows child IDs, receipts and uncertain states. UI and Host API both test pause/resume/revoke and lineage.

## 15 — paid self-hosted

Freeze each advertised `(OS, architecture, topology, release channel)` row independently: combined, separated, managed Hermes and hybrid are candidate topologies, not automatic support claims. For every PASS row, an independent person on a clean machine runs the public one-command bootstrap, verifies bootstrap trust/provenance and signed artifact, completes interactive setup, pairing and cross-node journey, then performs update, interrupted update, offline rollback, encrypted restore and lost-device revocation. Record machine/build, artifact digest, installer URL, actual command, duration and steps in `15-04-EVIDENCE.md`. Unsupported rows are excluded from marketing/install choices. Commercial terms, offline grace and entitlement mechanics require a reviewable `15-03` proposal and explicit owner checkpoint before implementation; expiry never blocks export, restore, deletion or security update.

## 16 — managed service

`16-01` must produce a reviewable trust/SLO design before owner approval. The control plane owns a minimal account principal and recovery method; add `internal/managed/auth.go`, `auth_test.go`, `cmd/lumen-managed/http_auth.go` and contract fixtures before provisioning is exposed. Every control-plane request authenticates account, binds tenant and role, checks CSRF/session or token audience as appropriate, and denies cross-tenant lookup before data-plane access. Recovery and operator access require separate audit and rate limit. `16-02` provisions only after the authenticated principal and approved region/key custody. `16-03` billing events change entitlement only after signature, tenant binding and idempotency. `16-04` staging uses two real isolated tenants; run wrong-tenant API/storage/backup/runtime probes, key rotation, restore, deletion, incident and RPO/RTO measurement. Test pass alone is insufficient.

## 17 — public extensions and shared Spaces

`17-01` drafts complete versioned public schema/compatibility policy first, then obtains owner approval before publication. `17-02` chooses one public SDK package (initial Go module `sdk/go` unless the owner approves another language), exports fixture parser/signature/manifest validation and a minimal node adapter API, and tests an independent fixture consumer from a clean temporary module with no `internal/` imports. Publication requires versioned package/tag and clean-checkout proof. `17-03` produces a role matrix for owner/member/guest across conversation, memory, artifact, grant, approval, node and export; specify invite/revoke/owner-loss/offline-member behavior and a migration design, then block on explicit owner and independent security approval. `17-04` adds membership store schema/migration, versioned Space reducer, every Host read projection and context export, effect policy/revalidation, protocol/client compatibility and backup/restore handling. Test mixed-private data before serialization and immediately after revoke at all APIs/streams; old clients fail closed.
