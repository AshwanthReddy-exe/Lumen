# Phases 07–10 executable handoff details

This supplements each `07-*` through `10-*` GSD plan. File paths below are task ownership; names of new functions are proposed. Before coding, inspect current callers and use an existing equivalent if it already enforces the same contract. Do not create a wrapper solely to match a proposed name. Every Host mutation uses the current `internal/store` transaction and `internal/space` reducer; Hermes, clients and nodes never acquire canonical Space write authority.

## Phase 07 — one bounded cross-node file action

**07-01 Mac node.** `Identity.swift` loads a Keychain-held device key, validates Host key/epoch from Phase 05 enrollment and signs a fresh challenge; public states are `unpaired`, `paired_offline`, `authenticated`, `stopped`, `revoked`. On local stop, reject new invocations before network cancellation. `node-v1.json` fixes node ID, key ID, protocol version, separate `files.search`/`files.read` capability IDs, local permission and manifest revision. `Files.swift` owns a node-local grant record `(capability, security_bookmark_id, root_file_id, expiry, revision)` and `search`/`read` handlers. Resolve a relative path under an owner-selected security bookmark through descriptor-relative, no-follow operations, then compare file identity/size before bounded read; reject traversal, symlink, replacement, nonregular target, inaccessible bookmark and oversized result. Host grant plus node-local grant plus current OS permission must all pass. No grant comes from pairing or capability advertisement. `IdentityTests.swift` exercises wrong/revoked key and stop; `FilesTests.swift` exercises one valid selected root and each denial. Physical Mac evidence records OS/build and one harmless canary path without its content.

**07-02 Host authorization.** Invocation v1 binds actor, source conversation, optional source message, selected target, capability/version, canonical argument digest, grant revision, approval ID, deadline and status. The Host selects only an eligible enrolled target and commits intent before transport. For ask, one Host update commits pending invocation and exact Phase 06 approval; no dispatch occurs until the accepted decision is consumed once. Go/Swift fixtures cover changed target, arguments, approval, version, nonce and bytes.

**07-03 ingress.** The Phase 03 authenticated HTTP router registers POST /v1/invocations with actor derived from session and conversation participation checked before broker use. A mapped documented Hermes plugin/tool callback reaches AcceptRuntimeCapabilityIntent in the Host Run consumer; its actor and conversation come from the persisted Run, and only typed allowlisted capability/arguments pass to the same broker. If the pinned callback is absent, mark model-originated action UNSUPPORTED and Phase 07 exit BLOCKED; model prose never substitutes.

**07-04/05/06 dispatch and proof.** Plan 07-04 authenticates the exact target, revalidates its local grant/OS permission and commits accepted/final receipts in its private durable store before acknowledging. Plan 07-05 resumes one exact approved invocation, commits verified receipt and redacted event in the originating conversation, exposes receipt/cancel and permitted local-outcome routes, and renders the replayed status in the web conversation. Plan 07-06 injects before/after-effect disconnects and proves the physical source-to-different-target journey with independent authorization review. The Mac owner-console grant-root/search/read commands from 07-01 are the reachable same-node LocalAction caller and enforce one-time local ask.

## Phase 08 — local voice without authority transfer

**08-01 engine/permissions.** Before writing the adapter, record selected on-device wake engine, model checksum, ABI, license and exact device/OS in `08-EVIDENCE.md`; if unavailable, tap-to-talk is the supported path and wake remains `UNSUPPORTED`. `VoiceMode.kt` owns `idle`, `muted`, `detecting`, `listening`, `interrupted`, `offline`, `degraded`. A monotonically increasing capture generation invalidates late callbacks after mute/stop/revoke/suspend. The microphone permission and visible indicator gate capture; zero audio bytes cross the process/network boundary before local wake. Test state transitions with fake audio, then observe physical egress with device traffic capture or counters during negative audio. E6 requires at least 100 intended attempts, at least 95 detected, eight hours negative audio and at most one false activation/hour under recorded conditions. Raw audio is removed after scoring; do not claim universal wake support from one device.

**08-02 transcript/playback.** `SpeechPipeline.kt` distinguishes provisional local text from one committed transcript tied to Phase 05 outbox command ID. Recognition duplicate callbacks cannot create a second Host message; after uncertain send, query receipt with the same ID. Local TTS belongs to the device; speaking is not a Space action receipt. Stop, mute, permission loss and barge-in invalidate capture/playback generation and terminate audio before another callback. If local recognition unavailable, show `degraded`; no automatic remote speech. Before E7 runs, owner preregisters numeric task accuracy, p95 latency, battery/thermal and interruption thresholds because `docs/PLAN.md` lists dimensions but not numbers. `SpeechDeviceTest.kt` records quiet/noisy, echo, sustained-use and failure observations on named Android hardware. Any unmeasured claim remains `BLOCKED`.

**08-02 selected desk identity and action handoff.** The existing `apps/android-host/` desk companion remains a separate application. Read the owner-approved D-056 result first: `PASS_SHARED` creates its own owner-confirmed Phase 05 Android Keystore-backed enrolled node credential; `FAIL_SHARED_SELECT_FALLBACK` reuses this app's Phase 05 `Pairing.kt` identity and `Outbox.kt`; `BLOCKED` stops. No phone-app private key or cross-process outbox import is permitted. `DeskIdentity.kt` gates authenticated transcript and event requests, while `CompanionEvents.kt` projects the canonical conversation, Phase 06 attention and Phase 07 invocation/receipt events into `VoiceMode` and the Activity. A spoken action remains normal conversation input until a mapped Hermes typed callback reaches the Host broker; an authorized Phase 06 surface resolves any approval. The physical voice journey must show one transcript, exact approval, selected target and same-conversation receipt or mark the action path `BLOCKED/UNSUPPORTED`.

## Phase 09 — integrated local acceptance

**09-01 real timeline.** Start from one clean Space under documented current setup; record Host, Hermes/profile, D-061 default NVIDIA NIM model (or separately approved profile), source, approval and target node revisions. In one canonical conversation: send a real-provider question, accept then correct memory, start a bounded Run, request the exact `files.read` canary on a *different* selected node, resolve its approval on an authorized surface, receive one target receipt, disconnect source and resume same conversation/Run/message IDs. `personal_alpha_local_test.go` uses fakes only for deterministic state assertions and is labeled simulated. The live evidence row records redacted IDs, timestamps, actual launch command and PASS/FAIL/BLOCKED for each hop; no prompt, file content or credential. `host_restart_test.go` and the Phase 07 `node_disconnect_test.go` cover before/after Run mapping, approval commit, node acceptance and result ACK. Unknown effect remains uncertain.

**09-02 failure and quality.** `phone_suspend_test.go` asserts lost ACK keeps one message; `storage_full_test.go` asserts no acknowledged partial commit and old data readable. `accessibility_test.go` may assert semantic state contracts but does not replace physical/browser observations. Record keyboard, label, focus, 200% text and reduced-motion checks separately for web, selected phone client and desk screen, with build/browser/OS IDs. `local_benchmark_test.go` records workload, denominator, p50/p95 route latency, Host memory/CPU and storage growth; thresholds must be preregistered in `09-EVIDENCE.md` or cited from `docs/PLAN.md` before measurement. Authorization/security review is independent of implementation author. Phase 09 cannot pass Phase 10's laptop-off or installer claims.

## Phase 10 — install, recovery and alpha exit

**10-01 one command.** `scripts/install.sh` is the minimal platform/bootstrap selector; the accepted D-054 GitHub Release tag/asset URL, bootstrap checksum and public signing-key fingerprint are frozen before publication. Its own downloaded source executes before artifact verification, so publish an independently checkable bootstrap checksum/package-manager alternative and state that trust boundary truthfully. It detects supported OS/arch, obtains signed manifest and artifact into a private temp path, verifies bytes before executing the artifact, installs a user-owned generation and starts interactive `lumen setup`. `cmd/lumen/main.go` reuses existing `internal/setup` planner/journal: wizard asks Host placement/profile, combined vs external Hermes, provider credentials through protected input and pairing. Existing Hermes config is never overwritten. Test wrong signature, truncated artifact, unsupported OS, interrupted install, rerun and resumed wizard; a fresh physical/VM machine must prove each advertised row.

**10-02 boot.** Linux systemd and Docker profiles have different lifecycle owners; `supervisor.go` chooses only a profile proven in setup journal. On a disposable VPS, prove anonymous pinned-image pull, fresh install, rerun, real reboot and same Space ID/running digest after boot. macOS LaunchAgent is user-login scoped; prove actual logout/login or reboot plus interrupted plist publication, or mark that auto-start profile unsupported. Doctor reads authenticated Host readiness, journal generation and runtime health; process liveness alone is insufficient. Record OS/arch, image digest, service identity and elapsed recovery.

**10-03 release/external runtime.** Extend existing `internal/setup/release.go` `ReleaseRecord`; do not create a parallel generation authority. Verify second signed generation and schema compatibility before publication, retain old bytes, recover interruption before/after publication, perform offline rollback, and reject incompatible downgrade. External Hermes on a second named machine must have pinned TLS identity/scoped credential and harmless real Run create/status/stream plus wrong-peer/auth and stream-loss cases. Host does not adopt external runtime lifecycle. Record actual containment or mark unsupported.

**10-04 backup/migration.** `internal/store/snapshot.go` freezes one transaction watermark across every canonical record family; archive manifest includes schema, IDs/counts/digests and watermark. Encrypt/authenticate before external storage. Restore into an empty replacement only after full verification; wrong key, tamper, partial archive and incompatible schema leave it empty. Owner manually quiesces old Host and resolves ambiguous effects before replacement activation. New Host epoch/key is acknowledged by each critical node; offline nodes remain unavailable; old Host return is denied by nodes and clients. No unilateral fence of a partitioned old Host and no automatic failover claim. Test on two named machines.

**10-09 release acceptance.** Turn off the original laptop physically, continue the same Space from another source while the supported Host remains reachable, then use an awake selected target for exact approved action and same durable receipt. Record an FR-by-FR evidence ledger for alpha requirements owned by Phases 01–10; do not claim Phases 11–17 complete. Seven *elapsed* days of soak record uptime, p95 route latency, memory/storage trend, restarts, interventions and gaps against predeclared thresholds. A simulated `soak_test.go` cannot substitute for elapsed duration. Owner signs the exact OS/arch/topology/model/device support matrix after reviewing negative and recovery evidence; otherwise alpha remains `BLOCKED`.
